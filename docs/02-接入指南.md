# 接入指南

> 目标：在新项目或老项目里，用最少步骤接上"检查 → 验签 → 下载 → 替换 → 重启"的完整更新链路。
> 设计与原理见 [01-更新功能说明.md](01-更新功能说明.md)。

## 0. 前置条件

| 需要 | 说明 |
|---|---|
| Windows 10/11 x64 | 当前验证过的平台 |
| Rust | 编译更新器；本地没有也行，CI 会编 |
| MSVC / MinGW | 编译 GUI 客户端 |
| GitHub 仓库 | 发布 Release（Gitee 可做镜像，资产同步即可） |

## 1. 五分钟接入（新项目）

```powershell
cd D:\code
git clone <本仓库地址> updater-source
cd updater-source

powershell -ExecutionPolicy Bypass -File scripts\scaffold-update.ps1 `
  -TargetDir D:\code\my-app `
  -Repo "我的账号/my-app" `
  -ExeName "MyApp.exe" `
  -Product "my-app" `
  -Homepage "https://github.com/我的账号/my-app" `
  -WindowTitle "MyApp — 版本更新"
```

生成：

```
my-app/
├── updater.conf                  # 已按参数写好
├── Cargo.toml  build.rs  src/    # Rust 更新器
├── resources/update-trusted-keys.json
├── client/                       # C++ GUI（src/gui.cpp + 构建脚本）
├── scripts/                      # 密钥、签名、配置头生成、脚手架
├── docs/                         # 本套文档（随项目走）
├── .github/workflows/update-release.yml
├── CHANGELOG.md                  # 0.1.0 模板（新增/修改/删除）
└── README-UPDATE.md
```

验证编译：

```powershell
cargo build --release                        # target\release\generic-updater.exe
set MSVC_SETUP=E:\打包\NuitkaGUI\msvc\setup_x64.bat
client\build-msvc.bat                        # dist\GuiUpdaterDemo.exe
```

## 2. 接进已有项目

把上面生成的内容整体放进子目录：

```
my-app/
├── （原有工程…）
├── updater/                ← scaffold 生成的文件都放这里
└── .github/workflows/update-release.yml
```

workflow 改两处：

```yaml
      - name: Build updater (Rust)
        working-directory: updater
        run: cargo build --release --target x86_64-pc-windows-msvc

      - name: Build GUI client (C++)
        shell: cmd
        run: updater\client\build-msvc.bat
```

打包步骤把 `dist\GuiUpdaterDemo.exe` 换成项目真实产物；更省事的是让原 CI 先出 exe，
用 `upload-artifact` / `download-artifact` 取过来。

## 3. 配置（改一次，编译进 exe）

```ini
repo=我的账号/my-app
feed_name=latest-version-windows-x64.json
exe_name=MyApp.exe               # 更新后要拉起的程序，不是 generic-updater.exe
homepage=https://github.com/我的账号/my-app
variant=portable                 # portable / online / offline
platform=windows-x64
interval_hours=24                # 自动检查最小间隔
startup_check_delay_seconds=30   # 界面显示后延迟再检查
product=my-app                   # 必须与 feed.product 一致
window_title=MyApp — 版本更新
require_signature=false          # 先跑通再开签名
```

改了 `updater.conf` 必须重新构建、重新发版，因为它是编译期常量。

## 4. 首次发布

1. 在 `CHANGELOG.md` 写当前版本小节（顺序固定：新增 → 修改 → 删除，一行一条）；
2. 提交并打 tag：

   ```powershell
   git add -A; git commit -m "feat: bootstrap updater"
   git tag v0.1.0
   git push origin main --tags
   ```

3. CI 产出三个资产：
   `latest-version-windows-x64.json`、`<product>-0.1.0-windows-x64-portable.zip`、`.zip.sha256`；
4. 下载 zip 解压运行，界面应显示「当前已是最新版本」。

> **发版规则（重要）**
>
> - 有代码提交要发版：`git tag vX.Y.Z && git push origin vX.Y.Z`，由 CI 自动出包；
> - 手动 Run workflow 会拿 `Cargo.toml` 的 `version` 当 tag。不改版本号就会和上一次抢同一个 tag
>   （`v0.5.5`、`v0.5.8` 就是这样产生的），所以除非确实要复用版本号，否则不要手动跑；
> - 版本号只由 tag 决定，`Cargo.toml` 的 version 不参与资产名和 feed；
> - 当前版本：0.6.0。

## 5. 验证一次真实更新

1. `CHANGELOG.md` 加 0.1.1 小节；
2. 打 `v0.1.1` 并 push；
3. 旧窗口点「检查更新」→ 出现 0.1.1 + 更新日志 + 大小 →「立即安装」→「重启软件」；
4. 重启后：
   - 标题/底部显示新版本；
   - `version.txt` 由新包替换；
   - 安装目录只剩程序、`version.txt`、隐藏清单 `.update-files.json`；
   - 新版本删掉的文件不会残留。

## 6. 开启签名（推荐）

```powershell
powershell -ExecutionPolicy Bypass -File scripts\new-release-key.ps1 `
  -PrivateKeyPath D:\keys\update-signing.pem `
  -PublicKeysPath resources\update-trusted-keys.json `
  -KeyId my-app-2026-01
```

1. 私钥整段（含 BEGIN/END）放进 GitHub → Settings → Secrets → Actions，
   名字必须是 `UPDATE_SIGNING_KEY`；
2. 提交 `resources/update-trusted-keys.json`；
3. `updater.conf` 改 `require_signature=true`；
4. 打新 tag。

之后每次发版 CI 自动签名。发布后自查：

```powershell
generic-updater.exe --verify-feed latest-version-windows-x64.json
# 签名有效: keyId=my-app-2026-01 version=0.1.1 packages=1
```

> 密钥只配一次。私钥丢了就再也签不出老客户端认的包，务必备份。
> 轮换：`keys` 数组追加新公钥（新 id）→ 发过渡版本 → 再移除旧公钥。

## 7. 主程序对接（不用 GUI 时）

任何语言都可以直接调更新器，按行读 stdout 的 JSON：

```text
启动：      generic-updater.exe --check --auto
用户同意：  generic-updater.exe --download
用户重启：  generic-updater.exe --apply --parent-pid <自己的 PID>  然后自己退出
```

退出码：`0` 无更新 / `2` 有更新或成功 / `1` 失败。

界面只需要三种状态：`Available`（版本+日志+大小）、`Downloading`（进度）、
`Ready`（显示「重启软件」）。

## 8. 发版清单

- [ ] `CHANGELOG.md` 有当前版本小节（新增/修改/删除）
- [ ] `git tag vX.Y.Z && git push origin vX.Y.Z`
- [ ] CI 成功，Release 有三件资产
- [ ] `latest-version-windows-x64.json` 首字符是 `{` 且含 `payload`（签名模式）
- [ ] 旧版本完整走一遍「检查 → 安装 → 重启」

## 9. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| feed 是明文，没有 base64 | 没配 `UPDATE_SIGNING_KEY`，签名步骤被跳过 |
| CI 报 `require_signature=true 但没有 secret` | 配 secret，或先设 false |
| CI 报公钥文件为空 | 先跑 `scripts/new-release-key.ps1` 并提交公钥 |
| PowerShell 5.1 报中文语法错误 | 脚本需 UTF-8 BOM（仓库内脚本已带）；自改脚本注意编码 |
| `sign-feed.ps1` 报需要 PowerShell 7 | 签名脚本用 `pwsh`（CI 默认就是），密钥生成用 5.1 即可 |
| 提示"已是最新"但明明有新版本 | 24h 内走缓存；手动「检查更新」强制联网核对 |
| 更新后重启两次 | 旧版本启动探测误判；0.5.4 起已修 |
| 安装目录出现 `.app-update` / `skipped-version.txt` | 0.5.2 遗留；0.5.4 起缓存与跳过状态都移出安装目录 |
| 沙箱报 notepad.exe 行为 | 包里带了 `README.txt`；0.5.9 起已移除 |
| 杀软报 HEUR/Trojan.Kryptik | 无签名 + 更新器行为的启发式误报，见下节 |

## 10. 杀软误报怎么处理

更新器天然会"下载 → 替换 → 重启"，容易被启发式标记。按收益排序：

1. **Authenticode 代码签名**（OV/EV）：最有效，SmartScreen 与启发式都会明显改善；
2. 向 Avira / Bkav / Rising 提交误报（附源码地址 + SHA256），一般 1~3 天加白；
3. 保持发布包干净（不带 README、不带额外工具）、版本信息完整；
4. 不要在发布物上加壳/压缩壳。

## 11. 迁移旧项目检查清单

- [ ] `repo` / `exe_name` / `product` 与项目一致
- [ ] `exe_name` 是**被更新的程序**，不是更新器
- [ ] workflow 打包的是真实产物
- [ ] `CHANGELOG.md` 当前版本有「新增/修改/删除」
- [ ] 需要签名时：secret、公钥、`require_signature=true` 三者一致
- [ ] 首次发布后跑 `--verify-feed`
- [ ] 用旧版本完整走一遍更新并检查安装目录是否干净

# 更新功能说明

> 这份文档讲"它是什么、怎么工作、为什么这么设计"。接入步骤见 [02-接入指南.md](02-接入指南.md)。

## 1. 目标

给任何 Windows 桌面程序加一个可复用的自动更新能力，要求：

- 用户侧：启动时静默检查（24h 节流）、手动检查、进度条、变更日志、跳过版本、重启完成；
- 工程侧：更新器与主程序解耦，主程序任何语言都能接；发布只产出一个 exe；
- 安全侧：元数据签名（RSA-PSS）、包 SHA256、下载源固定、失败/断电可回滚；
- 运维侧：CI 一条龙出包，配置编译期固化，密钥只配置一次。

## 2. 组成

```
┌─────────────────────┐   stdout JSON 帧    ┌──────────────────────┐
│  客户端 GUI (C++)   │ ──────────────────► │  更新器 (Rust)        │
│  按钮/进度/更新日志  │ ◄────────────────── │  检查/验签/下载/安装   │
└─────────────────────┘                     └──────────┬───────────┘
                                                       │ GitHub Release
                                                       ▼
                                    latest-version-windows-x64.json（签名）
                                    <product>-<version>-windows-x64-portable.zip
                                    <...>.zip.sha256
```

| 部分 | 职责 |
|---|---|
| `generic-updater.exe` | 唯一有权做网络、验签、写文件、拉起的进程 |
| 客户端 GUI | 只做 UI 与进程协调，不碰网络与安装 |
| feed | 一次发布的完整契约：产品、平台、版本、说明、包路径/大小/SHA256，整体签名 |
| CI | 编译两端 → 打包 → 算哈希 → 签名 → 发布 |

## 3. 版本与命名

- **版本只由 tag 决定**：`v0.5.4` → `0.5.4`；`v1.5.7_snow-shot` → `1.5.7`（`_` 后后缀丢弃）。
  `Cargo.toml` 的 version 只是工具自身编号，不参与发布。
- 资产命名：
  - `latest-version-windows-x64.json`
  - `<product>-<version>-windows-x64-portable.zip`
  - `<product>-<version>-windows-x64-portable.zip.sha256`
- 多平台就再加 `latest-version-windows-arm64.json` 等，客户端只认自己那份。

## 4. 配置（编译期）

`updater.conf` 是唯一配置源，构建时分别注入：

- Rust：`build.rs` 生成常量编进 `generic-updater.exe`；
- C++：`tools/gen-app-config.ps1` 生成 `app/build-config.h` 编进 GUI。

```
repo / feed_name / exe_name / homepage / variant / platform
interval_hours / product / window_title / require_signature
```

发布包因此只有一个 exe + version.txt，不需要 ini，用户改不了也丢不了。
调试时可用 `--config xxx.json` 或 `UPDATER_CONFIG` 环境变量临时覆盖。

## 5. 检查机制

| 场景 | 行为 |
|---|---|
| 启动自动检查 | 界面显示后延迟 `startup_check_delay_seconds`（默认 30s），且距上次成功检查 ≥ `interval_hours` 才联网 |
| 24h 内再次打开 | **不联网，但会用缓存结果提示"有更新"**（不会假报"已是最新"） |
| 手动「检查更新」 | 无视间隔，立即联网 |
| 检查失败 | 不刷新时间戳，下次启动重试 |
| 用户跳过某版本 | 记进 `state.json`，仍提示有更新但标注「已跳过」并禁用安装 |

关键状态都存缓存目录的 `state.json`：

```
last_check_unix        上次成功检查时间
last_remote_version    上次查到的远端版本（用于 24h 内提示）
last_remote_notes/size 更新日志与包大小缓存
skipped_version        用户跳过的版本
pending_*              已下载待安装的版本/暂存路径
```

## 6. 状态机与协议

客户端与更新器之间是 **stdout 一行一条 JSON**：

```json
{"protocol":2,"type":"status","state":"Available","version":"0.5.4",
 "notes":"…","received":0,"total":1214668,"error":null,
 "automatic":true,"skipped":false}
```

状态：`Unavailable / Idle / Checking / Available / Downloading / Verifying /
Ready / Applying / Failed`（与 snow-shot 的 `UpdateState` 对齐）。

- `automatic`：这次检查是自动还是手动；
- `skipped`：该版本是否被用户跳过；
- `received/total`：下载进度；`Available` 帧里的 `total` 就是包大小。

## 7. 更新流程

```
--download : Checking → Available → Downloading → Verifying → Ready
--apply    : Applying → 备份/覆盖/清理 → 拉起新版 → 启动探测 → Ready
```

1. **下载**：流式写入 `.part`，边下边算 SHA256，大小/哈希不符直接丢弃；
2. **暂存**：校验通过才解压到 staging；
3. **安装**：覆盖前写 journal；逐文件备份后覆盖；删除"旧版本有、新版本没有"的文件；
4. **拉起**：detached 启动新版，3 秒内进程没退出就算启动成功（不依赖标记文件）；
5. **回滚**：任一步失败按备份还原 exe、版本号与新增文件。

## 8. 安装事务与恢复

- `journal.json`：覆盖前记录「目标文件 + 备份路径」，装完标记 `committed`；
- 启动时 `--recover`：发现未提交事务就按备份还原（断电/崩溃场景）；
- `installed.json`：安装文件清单，升级时清理旧文件；
- 备份、暂存、下载都放**缓存目录**，安装目录只留程序本体。

## 9. 缓存与清理

```
%LOCALAPPDATA%\GenericUpdater\updates\<安装目录哈希>\
  ├── state.json       检查/跳过状态（长期保留）
  └── state.json / installed.json（旧版本遗留，0.5.7 起清单移到安装目录）
  ├── staging/ backup/ 安装期间临时（成功后删）
  └── *.zip *.part     下载缓存（成功后删）
```

系统缓存不可写（受限账户/安全软件）时回退到 `<安装目录>\.app-update` 并打日志。
0.5.2 及更早版本在安装目录留下的 `.app-update` 会在升级时清掉。

## 10. 签名

- 信封：`{"schema":1,"keyId":"…","payload":"<base64>","signature":"<base64>"}`；
- 签名对象：payload 的**原始 UTF-8 字节**；
- 算法：RSA-PSS + SHA-256 + salt 32，密钥 3072 位；
- 公钥编译进 exe（`resources/update-trusted-keys.json`），私钥只存 GitHub Secret；
- 客户端 `require_signature=true` 时拒绝任何明文/签名不符的 feed。

密钥只配一次；轮换时往 `keys` 数组追加新公钥、发过渡版本，再移除旧的。

## 11. 进程协调与权限

| 场景 | 做法 |
|---|---|
| 等主程序退出 | `OpenProcess + WaitForSingleObject`，拿不到句柄视为已退出 |
| exe 被占用 | 文件占用重试 90s 兜底 |
| 安装目录不可写 | `ShellExecuteW("runas")` 提权重启自身 |
| 更新器自更新 | 运行中的 exe 先改名 `*.old-<pid>` 再写新文件，下次启动清理 |
| 重复启动 | 客户端互斥体 + 重试，避免重启瞬间误判 |
| 新版起不来 | 启动探测失败 → 回滚 + 拉起旧版 |

## 12. 已知限制

- 不支持增量，每次整包下载；
- 没有 Authenticode 证书，SmartScreen 仍提示未知发布者；
- 极端断电（journal 写一半）可能残留，需要 `--clean`；
- 平台只验证了 Windows x64。

# 更新流程测试台

这个目录是纯前端实现，用来在**不装 Rust、不打包 exe** 的前提下，先把更新交互和状态机验证一遍。
逻辑与 `src/update.rs` 对齐：同样的状态名、同样的 24h 间隔、同样的 SHA256 校验、同样的清理与拉起顺序。

## 启动

```powershell
cd demo
node server.mjs
# 浏览器打开 http://127.0.0.1:8124/
```

`server.mjs` 只是静态服务器 + 一条 `/feed/portable` 路由（返回 zip 的字节）。
之所以不用 `python -m http.server`：本机安全软件会拦截 URL 以 `.zip` 结尾的浏览器请求，返回 204 空响应，下载步骤必然失败。真实更新器用 reqwest 不受影响。

## 建议按这个顺序点一遍

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 直接打开页面 | 500ms 后自动检查，状态变 `Available`，右侧出现 v1.2.0 和变更说明 |
| 2 | 看"距下次自动检查还有…" | 显示 24 小时倒计时 |
| 3 | 点 **立即更新** | 进度条走满，日志里出现 `Downloading`（带 received/total）→ `Verifying` → `Ready` |
| 4 | 点 **重启软件** | 依次显示备份/覆盖/清理，右上角版本变成 `1.2.0`，`pending` 被清空 |
| 5 | 再点 **模拟一次"打开软件"** | 日志不新增 `Checking` 帧，提示"距上次检查不足设定间隔，跳过" |
| 6 | 点 **手动检查（刷新）** | 无视 24h 限制，联网后提示"已是最新版本（v1.2.0）" |
| 7 | 点 **重置演示数据** | 回到 1.0.0 初始状态 |

## 另外两个要手动验证的分支

**校验失败**：把 `feed/latest-version-windows-x64.json` 里的 `sha256` 改掉任意一位，重新走一遍流程，应该停在 `Failed` 并显示
`SHA256 不一致：期望 xxxx…，实际 yyyy…`，且状态帧里 `error` 字段同步带出原因。

**版本号不合法**：把 `feed` 里的 `size` 改成比实际大的值，会得到 `大小不符` 的错误——这正是"下载被中途截断"的表现。

## 它没有覆盖的部分

浏览器里无法真的替换文件、也无法拉起进程，所以下面这些只有 Rust 版能验：

- `.part` 临时文件 + 原子改名落地；
- 旧文件备份、失败回滚；
- 运行中 exe 被占用时的重试；
- detached 方式拉起新版；
- 真正删除 `.app-update/` 缓存目录。

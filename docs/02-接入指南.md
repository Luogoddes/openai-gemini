# 接入指南

> 目标：把一个项目接上"检查 → 签名 → 下载 → 备份替换 → 重启"的完整更新链路。
> 功能与设计见 [01-更新功能说明.md](01-更新功能说明.md)。

## 0. 前置条件

| 需要 | 说明 |
|---|---|
| Windows 10/11 x64 | 已验证平台 |
| Rust（或 CI） | 编译 `generic-updater.exe`；本地没有也可以，CI 会编 |
| MSVC | 编译 GUI 客户端；或用 MinGW g++ |
| GitHub 仓库 | 发布 Release 用（Gitee 可做镜像，feed 资产同步即可） |

## 1. 一条命令生成更新模块

在**新项目**里（或空目录）执行：

```powershell
cd D:\code
git clone <本仓库地址> updater-source        # 或直接复制现有目录
cd updater-source

powershell -ExecutionPolicy Bypass -File tools\scaffold-update.ps1 `
  -TargetDir D:\code\my-app `
  -Repo "你的账号/你的仓库" `
  -ExeName "MyApp.exe" `
  -Product "my-app" `
  -Homepage "https://github.com/你的账号/你的仓库"
```

生成结构：

```
my-app/
├── updater.conf                  # 发布配置（repo/exe/product/间隔…）
├── Cargo.toml  build.rs  src/    # Rust 更新器
├── resources/update-trusted-keys.json
├── app/                          # C++ GUI（src/gui.cpp + 构建脚本）
├── tools/                        # 密钥、签名、配置头生成
├── .github/workflows/update-release.yml
├── CHANGELOG.md
└── README-UPDATE.md
```

然后在 `my-app` 里 `git init` 或把文件并进现有仓库即可。

## 2. 接进"已有项目"

已有项目通常不想被顶层 `Cargo.toml` 干扰，做法是整体放进子目录：

```
my-app/
├── （你原有的工程文件…）
├── updater/                ← 把上面生成的这些文件都放这里
│   ├── Cargo.toml  build.rs  src/  app/  tools/  updater.conf
└── .github/workflows/update-release.yml
```

需要改 workflow 的两处：

```yaml
      - name: Build updater (Rust)
        working-directory: updater
        run: cargo build --release --target x86_64-pc-windows-msvc

      - name: Build GUI client (C++)
        shell: cmd
        run: updater\app\build-msvc.bat
```

打包步骤里把 `dist\GuiUpdaterDemo.exe` 换成你项目实际产出的 exe（例如 `build\MyApp.exe`），
`generic-updater.exe` 的路径相应变成 `updater/target/...`。
更省事的做法是让原项目 CI 先产出 exe，再用 `actions/upload-artifact` / `download-artifact` 取过来。

## 3. 改配置（只改一次）

`updater.conf` 每一项都会被编译进二进制：

```ini
repo=你的账号/你的仓库          # 发布 Release 的地方
feed_name=latest-version-windows-x64.json
exe_name=MyApp.exe              # 更新后要拉起的程序名
homepage=https://你的官网        # GUI 上「官网下载」按钮
variant=portable                # portable / online / offline
platform=windows-x64
interval_hours=24               # 自动检查间隔
product=my-app                  # 必须和 feed 里的 product 一致
window_title=MyApp — 版本更新
require_signature=false         # 先 false 跑通，开了签名再改 true
```

## 4. 本地编译

```powershell
# 更新器
cargo build --release                       # target\release\generic-updater.exe

# GUI（二选一）
set MSVC_SETUP=E:\打包\NuitkaGUI\msvc\setup_x64.bat
app\build-msvc.bat                          # dist\GuiUpdaterDemo.exe

app\build-mingw.bat                         # 有全局 g++ 时
```

> 脚本是 UTF-8 BOM，Windows PowerShell 5.1 可正常解析；`tools/sign-feed.ps1` 需要 PowerShell 7（CI 用的就是 `pwsh`）。

## 5. 首次发布

1. `CHANGELOG.md` 里写 0.1.0 小节（新增/修改/删除，一行一条）；
2. 提交并打 tag：

   ```powershell
   git add -A; git commit -m "feat: bootstrap updater"
   git tag v0.1.0
   git push origin main --tags
   ```

3. CI 产出三个资产：`latest-version-windows-x64.json`、`*.zip`、`*.zip.sha256`；
4. 下载 zip 解压运行，界面应显示「当前已是最新版本」。

## 6. 验证一次真实更新

1. 改 `CHANGELOG.md` 加 0.1.1 小节；
2. 打 `v0.1.1` 并 push；
3. 旧窗口点「检查更新」→ 出现 0.1.1 + 更新日志 + 大小 →「立即安装」→「重启软件」；
4. 重启后 `version.txt` 变 0.1.1，标题/底部显示新版本。

## 7. 开启签名（可选但推荐）

```powershell
powershell -ExecutionPolicy Bypass -File tools\new-release-key.ps1 `
  -PrivateKeyPath D:\keys\update-signing.pem `
  -PublicKeysPath resources/update-trusted-keys.json `
  -KeyId my-app-2026-01
```

1. 私钥整段放进 GitHub Secret `UPDATE_SIGNING_KEY`；
2. 提交 `resources/update-trusted-keys.json`；
3. `updater.conf` 改 `require_signature=true`；
4. 打新 tag。

之后每次发版 CI 自动签名，不需要再配。发布后确认：

```powershell
generic-updater.exe --verify-feed latest-version-windows-x64.json
# 签名有效: keyId=my-app-2026-01 version=0.1.1 packages=1
```

## 8. 主程序对接（不用 GUI 时）

任何语言都可以直接调更新器，按行读 stdout 的 JSON：

```text
1. 启动时：generic-updater.exe --check --auto
2. 用户点更新：generic-updater.exe --download
3. 用户点重启：generic-updater.exe --apply --parent-pid <自己的 PID>，然后自己退出
4. 退出码：0 无更新 / 2 有更新或成功 / 1 失败
```

界面只需要三个状态：`Available`（显示版本+日志+大小）、`Downloading`（进度）、
`Ready`（显示"重启软件"按钮）。

## 9. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| feed 是明文，没有 base64 | 没配 `UPDATE_SIGNING_KEY`，签名步骤被跳过；配好 secret 再发版 |
| CI 报"require_signature=true 但没有 secret" | 要么配 secret，要么先设 false |
| CI 报"公钥文件里没有公钥" | 先跑 `tools/new-release-key.ps1` 并提交公钥 |
| PowerShell 5.1 报中文语法错误 | 脚本需要 UTF-8 BOM，仓库里的脚本已带；自己改脚本时注意编码 |
| 提示"已是最新"但明明有新版本 | 检查 tag 与 feed 的 `version` 是否一致；客户端 24h 内用的是缓存 |
| 重启了两次 | 旧版本启动探测误判；0.5.4 起已修，确认客户端版本 |
| 安装目录有 `.app-update` | 0.5.2 及更早的行为；0.5.4 起标记/缓存在 `%LOCALAPPDATA%` |

## 10. 迁移检查清单

- [ ] `updater.conf` 的 `repo` / `exe_name` / `product` 与仓库和程序一致
- [ ] `exe_name` 是**更新后要拉起的那个程序**，不是更新器自己
- [ ] `CHANGELOG.md` 当前版本有「新增/修改/删除」小节
- [ ] workflow 里打包的是项目真实产物
- [ ] 需要签名时：secret 已配、公钥已提交、`require_signature=true`
- [ ] 首次发布后跑一次 `--verify-feed` 确认签名
- [ ] 用旧版本完整走一遍「检查 → 安装 → 重启」
